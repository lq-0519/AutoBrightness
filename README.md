# 随光亮度

面向长安欧尚 X7 Plus F202_MCA（Android 9）的原生小工具，当前版本 1.1.0。桌面只有一个“随光亮度”图标，包含自动控制、亮度规则和设置三个页面。

需要安装两个使用相同发布签名的独立安装包：

- `com.codex.autobrightness`：设置界面，保留原桌面图标与已有配置，不包含控制服务和开机接收器。
- `com.codex.autobrightness.engine`：亮度控制后台，无 Activity、无桌面图标，独立 UID，持有车辆权限、前台服务与开机接收器。

先安装后台包，再覆盖安装设置包。升级后第一次打开设置会把旧配置迁移到后台；之后配置由后台独立保存，界面仅保留编辑镜像。默认开启自动调节、随车启动与唤醒恢复，初始曲线为 `0→20%、50→40%、200→70%、500→100%`。这些是可编辑起始值，光照原始数值未标定为 lux，白天可按体验调整。亮度按原厂整十档位输出，范围 10～100%。

支持平稳／均衡／灵敏三档响应、规则点增删改，以及手动接管 10 分钟／暂停到下次启动或唤醒／持续自动控制。关闭自动控制会停止后台服务并保持车辆当前亮度。

F202 原厂侧边“×”仍会强制停止当前设置包，但不会停止另一个 UID 下独立启动的后台包。界面关闭、解绑或 Binder 死亡仅移除状态回调，后台不依赖设置进程保活。停止自动亮度应使用界面中的自动调节开关。无需修改原厂 SystemUI，也不使用共享 UID、额外守护进程或定时拉活。

两个包通过原生 Messenger 通信，后台入口由签名级权限保护，并核对调用 UID 和签名。只在界面可见时推送状态；光照变化不会持续写配置。需要排查时，可按需运行 `adb shell dumpsys activity service com.codex.autobrightness.engine/com.codex.autobrightness.BrightnessService --live`。普通运行时不会因此新增周期任务。

后台使用光照变化通知和原厂亮度反馈，不定时轮询；只在确认变化、亮度过渡、暂停结束或连接恢复时安排有限任务。界面关闭后不刷新，屏幕休眠时取消车辆订阅。不申请网络或唤醒锁权限，光照数据不持续落盘。出站车辆 IPC 的完整请求、返回值和错误通过 `finally` 写入系统 JSON 日志。

## 构建

不依赖 Gradle、AndroidX 或网络库。使用以下固定版本工具：

- Android platform 28 r06：`platform-28_r06.zip`，SHA-1 `9a4e52b1d55bd2e24216b150aafae2503d3efba6`。
- Android Build Tools 35.0.1：`build-tools_r35.0.1_macosx.zip`，SHA-1 `f4dda6855ddf1ea1a51ee3ab6587104bd0c1d727`。
- JDK 17 或更新版本；应用字节码按 Java 8 编译。

工具来源为 Google 官方 Android SDK 仓库。运行 `python3 build.py --help` 查看参数，分别使用 `--module engine`、`--module app` 构建两个包。两次构建必须使用同一个签名密钥，构建目录和输出文件分别指定，且位于仓库外。后续升级也应沿用同一签名。

1.1.0 只进行编译、静态检查、签名和安装信息确认；不主动启动应用、点击“×”、调亮度或验证开机行为。实际功能、CPU、内存占用和车机自启动策略由用户实测。
